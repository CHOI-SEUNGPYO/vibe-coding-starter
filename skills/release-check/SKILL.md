# 게시 직전 확인

현재 요청에서 게시할 대상과 범위를 먼저 확인한다. 이미 사용자가 허용한 저장소 생성·push·PR 작업은 다시 허락을 묻지 않는다. 대상이나 공개 범위처럼 잘못 추정하면 결과가 달라지는 정보만 확인한다.

## 검토할 결과를 먼저 완성

- 실제 diff와 포함될 파일 목록을 확인한다. 환경변수 파일, 토큰, 개인 데이터, 실행 중 생성된 결과가 들어가 있지 않은지 살핀다. 비밀 값 자체를 출력하지 않는다.
- 검증 명령이 제품의 동작을 확인하는지 살피고 실행한다. 설정 파일 파싱이나 문서 검사는 제품 테스트와 구분한다. 빈 검증 목록을 성공으로 보고하지 않는다.
- 문서의 설치·실행 명령을 깨끗한 디렉터리에서 확인한다. 가져온 코드·스킬은 출처, 고정 버전, 라이선스와 필요한 고지를 함께 포함한다.
- README의 기능 설명과 실제 구현을 비교한다. 설정 예시는 연결 완료로, 로컬 테스트는 원격 CI 성공으로 표현하지 않는다.

## 게시와 결과 확인

현재 권한과 요청 범위 안에서 게시한다. 추가 승인이 실제로 필요하면 준비된 변경과 승인할 한 가지 동작을 구체적으로 보여준다. 권한 오류가 나면 인증 정보를 노출하지 말고 실패한 동작과 필요한 조치를 전달한다.

게시 후 원격의 대상 브랜치·커밋·공개 범위를 확인한다. CI 실행이 생겼다면 상태를 확인하고, 기다리기로 한 검사까지 완료한다. 네트워크나 권한 때문에 확인하지 못한 사항은 완료한 작업과 구분해 남긴다. 최종 안내에는 사용 가능한 링크와 중요한 검증 결과를 적는다.
