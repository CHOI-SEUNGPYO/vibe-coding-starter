# 첫 작업 지시 양식 — 데이터 분석

[README의 data 시작 순서](../README.md#데이터-분석으로-시작하기)를 따라 `python scripts/setup.py --profile data`를 실행하고, Codex에서 **저장소 루트**를 연 뒤 새 채팅을 시작하세요. 아래 코드블록은 채팅에 보내는 지시문입니다. 기술 선택을 모르겠으면 `추천해줘`, 해당하지 않는 항목은 `없음`으로 적습니다.

starter 자체는 Python 3.11 이상에서 실행되지만, 이번 독서 분석 예시의 잠금 의존성은 **Python 3.12 이상**이 필요합니다. Matplotlib뿐 아니라 함께 설치되는 NumPy·contourpy 등의 조건까지 확인한 결과입니다. 다른 프로젝트에서도 직접 선택한 라이브러리와 전이 의존성의 요구 버전을 함께 확인하고, 로컬 실행과 CI의 Python 버전을 맞춰야 합니다.

먼저 `[입력: ...]`을 채우세요. “CSV를 분석해줘”보다 **어떤 질문에 어떤 지표로 답할지** 적으면 결과를 확인하기 쉽습니다. 예를 들어 “완독일 기준 월별 완독 수와 페이지 합계, 평점을 남긴 완독 기록의 평균”처럼 기간과 분모를 함께 정합니다. 차트 형식은 [Observable Plot](https://observablehq.com/plot/), [Vega-Lite 예제](https://vega.github.io/vega-lite/examples/), [Matplotlib 갤러리](https://matplotlib.org/stable/gallery/index.html)에서 비교할 수 있습니다. 레퍼런스를 쓰기 위해 현재 기술 스택을 바꿀 필요는 없습니다.

개인 원본은 `apps/data/data/private/`, 공개해도 되는 가상 샘플은 `apps/data/samples/`, 결과는 `apps/data/output/`으로 나눕니다. `.gitignore`와 `git check-ignore`는 **이미 Git이 추적 중인 파일을 보호하지 않습니다.** 개인 파일이 추적되거나 이전에 게시됐다면 무시 규칙만 추가하고 해결됐다고 처리하지 말고, 게시 상태와 필요한 후속 조치를 따로 확인해야 합니다. 실제 원본 내용·개인정보·비밀키는 양식이나 외부 문서 검색에 넣지 마세요.

```text
$task-delivery로 아래 CSV 분석 프로젝트를 구현하고 검증해줘.

프로젝트 정보
- 이름: [입력: 예: reading-data]
- 목적과 사용할 사람: [입력: 예: 개인 독서 기록의 월별 변화와 읽는 상태를 확인]
- 사용할 환경: data
- 기술 스택: [입력: 예: Python 표준 csv + Matplotlib / 기존 스택 / 추천해줘]
- 실행할 Python 버전: [입력: 예: 독서 분석 예시는3.12 이상 / 잠금 의존성을 확인해 정해줘]
- 새 앱 위치: apps/data (기존 프로젝트가 있으면 현재 구조를 우선)
- 기존 코드·자료와 보존할 내용: [입력: 로컬 경로와 보존할 내용 / 없음]
- 이번에 제외할 기능: [입력: 예: 웹 화면, DB, 예측 모델, 클라우드 업로드]

입력 데이터
- 원본 경로: [입력: 예: apps/data/data/private/reading-log.csv / 먼저 가상 샘플을 만들어줘]
- 공개 샘플 경로: apps/data/samples/reading-log.csv
- 파일 형식과 인코딩: [입력: 예: 쉼표 구분 CSV, UTF-8 또는 UTF-8 BOM / CP949 / 확인해줘]
- 한 행의 의미: [입력: 예: 한 번의 독서 기록. 같은 책의 재독은 별도 record_id 사용]
- 열 이름과 조건: [입력: 필수 열·선택 열·자료형·허용값·단위]
  독서 예시: record_id, title, author, status, pages, rating, finished_date
  record_id는 중복 불가, title·author는 필수, status는 want/reading/done.
  pages는 1~100000의 정수, rating은 빈 값 또는 1~5의 정수, finished_date는 done일 때만 필수 YYYY-MM-DD.
- 날짜·시간 기준: [입력: 예: finished_date의 달로 집계, 시간대 변환 없음]
- 데이터 규모와 제한: [입력: 예: 개인 기록 수천 행 / 예상 행 수와 파일 크기 / 확인해줘]

분석할 질문과 지표
1. [입력: 예: 월별 완독 기록 수와 완독한 책의 페이지 합계]
2. [입력: 예: want/reading/done별 기록 수]
3. [입력: 예: 평점을 남긴 완독 기록의 평균 평점과 그 기록 수]
- 분석 기간과 포함 기준: [입력: 예: 전체 기간, 월별 지표에는 done만 포함]
- 합계·평균·비율의 분모: [입력: 예: 빈 평점은 0으로 바꾸지 않고 평균에서 제외, 분모도 표시]
- 기록이 없는 기간: [입력: 예: 첫 완독월과 마지막 완독월 사이의 빈 달은 0으로 표시]
- 결과 해석의 한계: [입력: 예: 기록한 책에 대한 요약이며 실제 독서 시간이나 독서 능력을 뜻하지 않음]

입력 오류 처리
- 누락·잘못된 값: [입력: 예: 필수값 누락·잘못된 날짜·숫자는 행 번호와 원인을 알리고 전체 실행 중단]
- 중복 기준과 처리: [입력: 예: record_id 중복 거부, 같은 제목·저자의 서로 다른 기록은 유지]
- 이상값과 경계: [입력: 예: 음수 페이지·NaN·무한대·허용 범위 밖 평점 거부]
- 빈 데이터: [입력: 예: 헤더만 있는 CSV는 0지표와 빈 상태 안내, 완전히 빈 파일은 입력 오류]
- 행을 제외하거나 보정해도 되는 범위: [입력: 예: 조용히 제외·보정하지 말고 입력 오류로 처리]

결과와 레퍼런스
- 필요한 결과물: [입력: 예: summary.json, monthly.csv, status.csv, 한국어 report.md, reading-summary.png]
- 차트 목적과 형식: [입력: 예: 월별 완독 수와 상태별 기록 수를 막대그래프로 비교]
- 참고할 사이트: https://observablehq.com/plot/ , https://vega.github.io/vega-lite/examples/ , https://matplotlib.org/stable/gallery/index.html
- 표시 언어·단위: [입력: 예: 한국어, 권·쪽·점, 평균의 분모 함께 표시]
- 저장 위치: apps/data/output/ 아래 실행마다 새 폴더. 기존 결과는 덮어쓰지 않아.

완료 조건과 게시 범위
1. [입력: 예: 가상 샘플을 분석한 표와 차트가 손으로 검산한 고정 기대값과 일치]
2. [입력: 예: 같은 CSV를 새 결과 폴더에 다시 분석해도 집계값이 같고 원본 해시가 유지]
3. [입력: 예: 잘못된 CSV·차트 생성 실패·출력 경로 충돌에도 원본과 기존 결과가 유지]
- 이번에 허용하는 범위와 대상: [입력: 로컬 구현·검증까지 / GitHub URL과 브랜치 / 지정한 공유 위치]

진행 방법
- AGENTS.md, docs/environments.md, docs/skill-routing.md를 읽고 data 프로필과 OpenAI Docs·Context7 연결을 확인해줘. data에는 스킬 8종과 문서 MCP 2개가 준비되지만 분석 프로그램과 의존성은 별도로 만들어야 해. 연결 실패를 성공으로 처리하지 마.
- 프로젝트의 Ponytail full과 python-patterns를 적용하고, 검토에는 Ponytail Review를 사용해줘. Postgres 지침은 실제로 Postgres를 쓸 때만 적용해줘. 작은 CSV 집계에 pandas·DB·웹서버를 필수로 넣지 말고 기존 코드와 표준 기능을 우선해줘.
- 추천 항목은 목적과 기존 코드에 맞게 선택한 뒤 구현을 이어가줘. 분석 결과를 바꾸는 모호한 기준은 먼저 짚어줘. 설치한 라이브러리·Python 버전을 확인하고 Context7 또는 공식 문서와 대조해줘. 직접 의존성뿐 아니라 잠금 파일의 전이 의존성까지 충족하는 Python 버전을 README와 CI에 반영해줘. 비공개 코드와 원본 행을 외부 검색에 보내지 마.
- 앱 전용 apps/data/.venv와 잠금 파일을 만들고 그 Python으로 의존성을 설치해줘. 가상환경 활성화나 전역 패키지·실행 정책 변경 없이 동작하게 해줘. 루트 MCP용 package.json·잠금 파일·설정은 보존해줘. Node 22 이상은 문서 MCP 검사에 쓰이며 Python 분석 의존성 설치를 대신하지 않아.
- apps/data/data/private/와 결과·가상환경은 Git에서 제외하고, 공개 가상 samples/와 테스트 자료는 추적할 수 있게 해줘. *.csv 전체를 제외하지 마. 개인 원본 경로의 무시 규칙과 이미 추적 중인 파일 여부를 둘 다 확인해줘. 원본은 읽기 전용으로 사용하고 입력 경로를 출력으로 덮어쓰지 마.
- CLI는 --input과 --output으로 경로를 받게 해줘. 기본 UTF-8은 BOM도 처리하고, CP949는 --encoding cp949로 명시하게 해줘. 글자가 깨지는 자동 추측이나 오류 무시는 피하고, 인코딩 오류 때 확인 방법을 안내해줘. 문서에 명령을 실행할 기준 폴더를 적고, 결과 열기 명령은 분석 성공을 확인한 경우에만 이어가게 해줘.
- 스키마·행 길이·중복 열·필수값·잘못된 숫자·날짜·제어문자를 확인해줘. 누락을 0으로 바꾸거나 잘못된 행을 조용히 버리지 마. 집계 정의와 실제 포함·제외 기준, 평균·비율의 분모를 표와 보고서에 명시해줘.
- 출력은 지정한 새 폴더에만 만들고 기존 폴더가 있으면 다른 이름을 안내해줘. 분석이나 파일 생성 중 실패하면 부분 결과를 완성된 보고서처럼 남기지 마. 원본과 기존 결과는 그대로 보존해줘.
- 차트는 GUI 없는 환경에서도 파일로 생성되게 해줘. Matplotlib이면 Agg 같은 비대화형 방식을 사용하고 한글 폰트를 준비해줘. 폰트를 번들하면 출처·버전·라이선스를 기록하고, 실행할 때 외부 폰트 서비스에 의존하지 않게 해줘. 차트의 0기준·축·단위·표본 수·빈 상태를 확인하고 실제 이미지를 열어 한글 깨짐과 잘림을 확인해줘.
- .vibe/project.json에 이 분석의 목표·완료 조건과 실제 검산·오류·재실행 검사를 등록해줘. Python 검사는 cwd:"apps/data", venv:".venv", command:["{python}", ...]를 사용해줘. CI는 현재 프로필 check → 런타임·가상환경 준비 → 잠금 의존성 설치 → verify 순으로 연결하고 공개 샘플·임시 폴더만 사용해줘.
- 작은 고정 데이터의 기대 합계·평균·월별 결과를 직접 정해 검사해줘. UTF-8 BOM·명시한 인코딩, 누락·중복·잘못된 값, 빈 목록, 한글, 원본 해시 보존, 새 폴더에 재실행한 결과 일치, 출력 실패를 확인해줘. 시간·난수를 쓰면 기준 시점과 seed를 고정해줘. PNG 바이트 일치와 집계값 일치는 구분해줘.
- python scripts/vibe.py verify와 실제 분석 명령을 모두 실행하고 결과 파일을 열어 확인해줘. starter 검사만 통과한 것을 분석 완료로 보고하지 마. 파일로 차트를 만드는 작업에 브라우저 검사를 필수로 추가하지 마. 웹 화면도 만든 경우에만 실제 브라우저 흐름을 확인해줘.
- 독립 작업에만 보조 에이전트를 쓰고 담당 파일을 나눠줘. README에 OS별 설치·실행·검사 명령, 샘플과 내 CSV를 분석하는 순서, 결과 위치와 해석 기준을 적어줘. 새 컴퓨터에 clone으로 복원하려면 먼저 앱 코드·공개 자료·잠금 파일·프로필 변경을 본인 저장소에 반영해야 한다는 점도 설명해줘. 마지막에는 실제 결과 경로·검증 결과·남은 제한을 알려줘. 게시가 범위에 포함되면 원본 데이터가 포함되지 않았는지와 원격 결과도 확인해줘.
```
