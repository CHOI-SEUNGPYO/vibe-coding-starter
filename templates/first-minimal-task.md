# 첫 작업 지시 양식 — 작은 도구와 수정

저장소 루트에서 `python scripts/setup.py --profile minimal`을 적용하고 Codex에서 새 채팅을 시작하세요. Python 3.11 이상이 필요하며, minimal 설정 자체에는 Node·MCP·브라우저 설치가 필요하지 않습니다. 기존 앱이 다른 실행 환경을 사용한다면 그 조건은 유지합니다.

이 양식은 작은 CLI나 범위가 분명한 수정을 위한 것입니다. `[입력: ...]`을 채워 코드블록 전체를 채팅에 보냅니다. 실행할 프로그램을 만드는 것과 starter 검사만 통과하는 것을 구분합니다. 독서 검색의 실제 코드는 [공개 예제](../examples/reading/minimal/README.md)에 있습니다.

```text
$task-delivery로 아래 작은 도구 또는 수정을 구현하고 검증해줘.

목적과 범위
- 이름과 해결할 문제: [입력: 예: 독서 JSON에서 원하는 책을 빠르게 찾기]
- 사용할 환경: minimal
- 새 도구인지 기존 수정인지: [입력: 예: 새 CLI / 기존 파일 경로와 현재 동작]
- 입력과 결과: [입력: 예: UTF-8 JSON 배열 → 조건에 맞는 책을 stdout JSON으로 출력]
- 핵심 기능: [입력: 예: 제목·저자 부분 검색과 읽는 상태 필터]
- 이번에 하지 않을 기능: [입력: 예: 파일 수정·DB·웹 화면·외부 API]

입력 계약과 완료 조건
- 필수 필드·자료형·허용값: [입력: 예: 양의 정수 id, 제목·저자, want/reading/done, 메모]
- 검색·정렬 기준: [입력: 예: NFC+casefold 검색, 원본 순서 유지]
- 빈 결과와 오류 처리: [입력: 예: 검색 결과 없음은 빈 배열과 성공, 잘못된 입력은 비정상 종료]
- 보존할 내용: [입력: 원본 파일·현재 API·저장 데이터 / 없음]
- 직접 확인할 대표 흐름: [입력: 예: 전체 조회 → 제목 검색 → 상태 교집합 → 없는 결과]
- 검증할 경계 조건: [입력: 예: 한글·BOM·누락·중복 ID·잘못된 타입·입력 해시 보존]
- 이번에 허용한 범위와 대상: [입력: 로컬 구현·검증까지 / GitHub URL과 브랜치]

진행 방법
- AGENTS.md와 현재 코드·실행 명령을 확인하고 프로젝트의 Ponytail full로 구현해줘. 이미 있는 코드와 표준 기능을 우선하고 목적에 필요 없는 프레임워크나 설정을 추가하지 마.
- 새 도구는 apps/minimal에 만들되 기존 프로젝트라면 현재 구조를 유지해줘. 앱 실행 환경은 확인한 버전으로 안내하고 루트 starter 설정과 잠금 파일은 보존해줘.
- minimal에는 공통 스킬6종과 MCP0개가 적용돼. 외부 도구가 필요하지 않으면 연결을 추가하지 마. 문서가 필요하면 사용하는 도구의 공식 문서를 확인해줘. Python CLI는 argparse/json/unicodedata를 우선 검토해줘.
- 입력 검증과 실패 시 기존 데이터 보존은 생략하지 마. 읽기 전용이면 실제 원본 해시가 변하지 않는지 확인하고, 파일을 쓰는 기능이면 출력 위치·기존 파일 처리 정책을 먼저 정해줘.
- 공개 가능한 가상 샘플과 임시 테스트 자료를 사용해줘. 개인 원본은 data/private/에 두고 Git 제외 규칙과 이미 추적된 파일 여부를 함께 확인해줘. 개인 내용은 외부 검색이나 공개 결과에 넣지 마.
- .vibe/project.json에 도구의 목표·완료 조건과 실제 검사 명령을 등록해줘. 필요한 경우 cwd를 앱 폴더로 지정하고 기본 starter 검사만으로 완료했다고 하지 마. 계속 실행되는 서버나 감시 프로세스를 검사 목록에 넣지 마.
- 정상 결과의 고정 정답, 결과 없음, 잘못된 입력, 비정상 종료 코드, 원본 보존을 검사하고 실제 CLI 명령도 실행해줘. 문제가 원래 있던 수정 작업이라면 변경 전 실패와 변경 후 성공을 확인해줘.
- 독립 작업으로 나눌 이점이 있을 때만 보조 에이전트를 쓰고, Ponytail Review로 관련 호출부와 변경을 검토해줘. GUI나 브라우저를 만들지 않았다면 브라우저 검사를 했다고 보고하지 마.
- README에 준비·실행·검사·샘플·내 파일 적용 방법과 제한을 적어줘. 공개 결과는 실제 명령에서 생성하고 어느 샘플을 썼는지 기록해줘. 마지막에는 바뀐 동작과 실제 검사, 남은 제한을 알려줘.
```

레퍼런스: [Python argparse](https://docs.python.org/3/library/argparse.html), [JSON](https://docs.python.org/3/library/json.html), [Unicode 정규화](https://docs.python.org/3/library/unicodedata.html). 다른 언어의 기존 프로젝트라면 그 언어의 표준 라이브러리와 현재 도구를 우선합니다.
