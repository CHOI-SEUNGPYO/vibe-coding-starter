# 첫 작업 지시 양식 — API

[README의 API 시작 순서](../README.md#api-개발로-시작하기)를 따라 `python scripts/setup.py --profile api`를 실행하고, Codex에서 **저장소 루트**를 연 뒤 새 채팅을 시작하세요. 아래 코드블록은 채팅에 보내는 지시문입니다.

1. `[입력: ...]`을 채웁니다. 기술 선택을 모르겠으면 `추천해줘`, 해당하지 않는 항목은 `없음`으로 적습니다.
2. API를 호출할 대상과 보관할 데이터를 먼저 정합니다. 화면이 없어도 정상 요청·오류·인증·저장 결과를 직접 확인할 수 있도록 완료 조건을 씁니다.
3. 실제 토큰·비밀키·개인정보를 양식에 넣지 않습니다. 로컬 설정 파일로 전달하고 Git에서 제외합니다.
4. [OpenAPI](https://spec.openapis.org/), [Swagger Petstore](https://petstore.swagger.io/)에서 요청·응답·인증 표현을 참고합니다. FastAPI라면 [자동 문서](https://fastapi.tiangolo.com/tutorial/first-steps/)와 [테스트 안내](https://fastapi.tiangolo.com/tutorial/testing/)도 확인합니다. 명세·라이브러리는 실제 설치 버전과 맞춥니다.

```text
$task-delivery로 아래 API의 첫 버전을 구현하고 검증해줘.

프로젝트 정보
- 이름: [입력: 예: reading-api]
- 목적: [입력: 누구의 어떤 문제를 해결하는지 한 문장]
- 호출 대상: [입력: 예: 이 컴퓨터에서 쓰는 개인용 클라이언트 / 웹앱 / 외부 서비스]
- 사용할 환경: api
- 기술 스택: [입력: 예: Python + FastAPI + SQLite / 추천해줘]
- 새 앱 위치: apps/api (기존 앱이 있으면 현재 구조를 우선)
- 기존 코드·자료와 보존할 내용: [입력: 경로와 내용 / 없음]

첫 버전의 기능과 계약
1. [입력: 예: POST /api/books로 제목·저자·상태·메모 등록, 201 반환]
2. [입력: 예: GET 목록·상세, 제목·저자 검색, 상태 필터, 페이지 조회]
3. [입력: 예: PATCH로 보낸 필드만 수정, DELETE로 삭제]
- 입력 조건: [입력: 필수 필드, 타입, 길이, enum, 공백·null·알 수 없는 필드 처리]
- 응답·오류 형식: [입력: 예: 기록은 id 포함, 오류는 error의 code/message/details]
- 이번에 제외할 기능: [입력: 예: 회원가입, 웹 화면, 외부 도서 검색, 운영 배포]

인증·저장·재시도
- 인증과 사용자 구분: [입력: 개인용 Bearer 토큰 / 계정별 인증 / 추천해줘]
- 사용자별 접근 권한: [입력: 예: 단일 사용자라 역할 구분 없음 / 본인 기록만 조회·변경]
- 저장할 데이터와 위치: [입력: 예: apps/api/data/books.sqlite3, 서버 재시작 후 유지]
- 외부 연동과 필요한 설정: [입력: 서비스명·용도·환경변수 이름 / 없음]
- 중복 요청 정책: [입력: 예: POST는 비멱등이며 자동 재시도 금지, DELETE는 반복해도204 / 추천해줘]
- PATCH 정책: [입력: 예: 생략한 필드 유지, 명시적null 거부, 빈객체는 변경없음]
- 실패 시 데이터 보존: [입력: 예: 잘못된 입력·DB쓰기실패는 기존 기록을 바꾸지 않음]

레퍼런스
- API 계약: https://spec.openapis.org/ 와 https://petstore.swagger.io/
- 프레임워크·DB: [입력: 현재 프로젝트 공식 문서 / 설치 버전에 맞게 찾아줘]
- 관리자 화면도 필요한지: [입력: 없음 / 필요한 화면과 범위]
  화면이 포함되면 docs/design-references.md의 SaaSFrame·Mobbin 공개 사례를 참고하고
  웹 개발 환경과 브라우저 검사를 별도로 준비해줘.

완료 조건
1. [입력: 예: 인증 후 등록 → 조회 → 부분 수정 → 재시작 → 다시 조회 → 삭제]
2. [입력: 예: 인증 누락·오류는401, 없는기록은404, 입력오류는422와공통오류본문]
3. [입력: 예: 한글·이모지 보존, 검색·필터·페이지 조회가 계약과 일치]
- 추가 실패·경계 조건: [입력: 예: DB잠금, 토큰미설정, 중복요청, 최대길이]

작업과 게시 범위
- 이번에 허용하는 범위와 대상: [입력: 로컬 구현·검증까지 / GitHub URL과 브랜치 / 배포 대상]

진행 방법
- AGENTS.md, docs/environments.md, docs/skill-routing.md를 읽고 api 프로필과 OpenAI Docs·Context7 연결을 확인해줘. 연결 실패를 성공으로 처리하지 마. API 설계, Ponytail을 적용하고, 검토에는 Ponytail Review를 써줘. Postgres 지침은 Postgres를 쓸 때만 적용해줘.
- 구현 전에 메서드·경로·상태코드·입출력·인증·재시도 정책을 짧게 정리하고, 응답 계약과 OpenAPI를 함께 맞춰줘. 추천 항목은 목적에 맞게 선택한 뒤 구현을 이어가줘. 단일 토큰과 사용자별 권한을 혼동하지 마.
- 루트의 MCP용 package.json·잠금 파일·설정을 보존해줘. 앱 의존성은 앱 폴더에 두고 잠금 파일을 만들어줘. Python이면 apps/api/.venv를 생성하고 해당 Python으로 설치해줘. Activate.ps1 실행이나 전역 Python 설치 변경 없이 동작하게 해줘.
- 설치 버전과 런타임 요구사항을 공식 문서로 대조해줘. API 프로필의 Node22이상 요구는 문서 MCP 확인용이며 Python 앱의 의존성 설치를 대신하지 않아. DB상대경로의 기준 폴더도 고정하고 설명해줘.
- 기본 토큰을 소스에 넣지 마. 로컬 인증이 필요하면 무작위 토큰을 Git에서 제외한 .env에 준비하되 기존 파일을 덮어쓰거나 토큰을 답변·로그에 출력하지 마. .env.example에는 설정 이름만 적어줘. DB·.venv·시험자료도 Git에서 제외해줘.
- .vibe/project.json에 목표·완료 조건과 실제 앱 검사를 등록해줘. Python 검사는 cwd:"apps/api", venv:".venv", command:["{python}", ...]를 사용해 루트의 python scripts/vibe.py verify가 앱의 가상환경으로 검사하게 해줘. 기존 환경 검사는 필요한 범위에서 유지해줘.
- CI는 커밋된 프로필을 check로 확인하고, 런타임 준비 → OS에 맞는 가상환경 생성 → 잠금 의존성 설치 → verify 순으로 맞춰줘. CI에서 web 프로필을 다시 설치하지 마. 사용자 인증정보와 개발 DB 없이 임시 DB·시험용 토큰으로 검사해줘.
- 정상 CRUD뿐 아니라 타입·길이·공백·제어문자·null·알 수 없는 필드, 인증누락·잘못된인증·설정누락, 없는ID, 검색·정렬·페이지 경계, PATCH·삭제·POST 재시도 정책을 검사해줘. 사용자별 권한이 있다면 다른 사용자 접근도 검사해줘.
- DB쓰기실패를 실제로 재현해 오류 응답과 기존 데이터 보존을 확인해줘. 서버를 실제로 종료했다 다시 켜도 같은 DB에서 기록이 조회되는지 확인해줘. 앱 객체만 다시 만드는 검사와 프로세스 재시작을 구분해줘.
- 계속 켜 둘 서버는 종료되는 검사 목록에 넣지 마. 시작 로그뿐 아니라 실제 HTTP로 health·OpenAPI·인증·대표 CRUD를 확인해줘. 테스트 클라이언트와 실제 HTTP의 결과를 구분해줘. 화면이 없는 API에 Playwright를 필수로 추가하지 마.
- 검사가 멈추거나 설치·접속이 실패하면 앱 오류인지 실행 환경의 DNS·로컬 소켓·포트 제한인지 구분해줘. 제한을 임의로 해제하지 말고 허용된 방법으로 검증해줘. 실행하지 못한 검사는 이유를 남겨줘.
- 독립 작업에만 보조 에이전트를 사용하고 담당 파일을 나눠줘. README에 OS별 설치·실행·검사·인증 방법과 복사해 쓸 HTTP 요청 예시, 재시작 후 데이터 위치를 적어줘.
- 마지막에 실행 방법·접속 주소·실제로 통과한 검사·남은 제한을 알려줘. starter 검사만으로 API가 완성됐다고 보고하지 마. 게시가 범위에 포함되면 대상과 원격 결과도 확인해줘.
```
