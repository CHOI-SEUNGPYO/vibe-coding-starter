# 첫 작업 지시 양식 — 반복 작업 자동화

`python scripts/setup.py --profile automation`을 실행하고 Codex에서 저장소 루트를 열어 새 채팅을 시작하세요. 자동화 프로필은 스킬10종과 OpenAI Docs·Context7·Playwright를 준비합니다. 파일만 다루는 작업은 브라우저가 필요하지 않으며, 외부 서비스에 보내는 동작은 실제로 요청한 범위에서만 만듭니다.

독서 주간 요약의 실행 가능한 예시는 [automation 예제](../examples/reading/automation/README.md)에 있습니다. [n8n 워크플로 사례](https://n8n.io/workflows/)에서 입력→변환→저장·실패 분기 구성을 비교하되 n8n 설치나 유료 서비스를 자동으로 추가하지 않습니다. Python 파일 처리는 [CSV](https://docs.python.org/3/library/csv.html), [tempfile](https://docs.python.org/3/library/tempfile.html)를 참고할 수 있습니다.

아래 `[입력: ...]`을 채워 채팅에 보냅니다. 비밀키·개인 원본·수신자의 민감한 정보는 양식에 적지 않습니다.

```text
$task-delivery로 아래 반복 작업을 구현하고 검증해줘.

프로젝트와 범위
- 이름: [입력: 예: reading-weekly]
- 목적: [입력: 예: 매주 독서 CSV에서 완독 기록을 요약]
- 실행 환경: automation
- 기술 스택: [입력: Python 표준 라이브러리 / 기존 스택 / 추천해줘]
- 앱 위치: [입력: apps/automation / 기존 앱 경로]
- 이번에 제외할 기능: [입력: 예: 웹 화면, DB, 실제 예약 등록, 이메일 발송]

시작 조건과 입력
- 트리거: [입력: 수동 실행 / 지정한 이벤트 / 일정 제안만 / 실제 등록할 일정과 대상]
- 입력 경로·형식: [입력: 예: data/private/reading.csv, UTF-8 BOM 허용 CSV]
- 필수 열·자료형·허용값: [입력: 구체적인 스키마 / 먼저 공개 가상 샘플로 정해줘]
- 기간·시간대: [입력: 예: --week의 월요일부터 일요일까지 완독일로 집계, 날짜만 있어 시간대 변환 없음]
- 누락·중복·잘못된 값: [입력: 예: 행 번호를 알려주고 전체 중단, 조용히 건너뛰지 않음]

처리와 결과
1. [입력: 예: CSV 검증과 해당 주 완독 기록 선택]
2. [입력: 예: 완독 수·전체 페이지 합·평점 평균과 분모 계산]
3. [입력: 예: Markdown과 JSON을 로컬 새 결과 폴더에 저장]
- 출력 위치: [입력: 예: apps/automation/work/output/]
- 원본과 기존 결과 보존: [입력: 예: 읽기 전용 원본, 기존 결과 덮어쓰기 금지]
- 레퍼런스: https://n8n.io/workflows/ 에서 같은 처리 흐름을 비교해줘.

실행·재시도·복구 정책
- 미리보기: [입력: 예: 기본은 dry-run, 파일·폴더를 만들거나 외부에 보내지 않음]
- 실제 실행: [입력: 예: --apply를 지정한 때만 로컬 결과 생성]
- 같은 작업을 식별하는 기준: [입력: 예: 원본 바이트 해시+주 시작일+처리 버전]
- 재실행 결과: [입력: 예: 같은 완료 결과가 실제로 일치하면 재작성 없이 이미 완료라고 표시]
- 입력이 바뀐 경우: [입력: 예: 새 실행 키로 따로 저장]
- 중간 실패: [입력: 예: 임시 산출물을 정리하고 원본·기존 결과 보존, 다음 실행에서 재시도]
- 완료 폴더의 필수 결과가 누락되거나 변조된 경우: [입력: 예: 완료로 간주하지 말고 오류, 자동 덮어쓰기 금지]
- 동시 실행 범위: [입력: 예: 개인용 순차 실행 / 동시 작업 수와 필요한 보장]

외부 연결과 게시 범위
- 외부 서비스와 권한: [입력: 없음 / 서비스명과 읽기·쓰기 범위]
- 메시지·파일을 보낼 대상과 동작: [입력: 없음 / 명시한 수신 대상과 전송 범위]
- 이번에 허용하는 범위: [입력: 로컬 구현·검증 / 특정 저장소 반영 / 특정 예약·전송 등록]

완료 조건
1. [입력: 예: dry-run은 파일 시스템과 외부 상태를 바꾸지 않는다]
2. [입력: 예: apply 후 같은 명령을 반복해도 중복 결과나 재전송이 없다]
3. [입력: 예: 잘못된 입력·부분 실패·변조 결과에서 기존 데이터를 보존한다]

진행 방법
- AGENTS.md, docs/environments.md, docs/skill-routing.md를 읽고 현재 프로필과 필요한 도구의 실제 연결을 확인해줘. 실패한 연결을 성공으로 보고하지 마.
- 프로젝트의 Ponytail full, Python일 때 python-patterns, 재시도·입출력 계약에는 api-and-interface-design을 적용해줘. 검토는 Ponytail Review로 해줘. 작업 크기에 맞는 표준 기능과 기존 코드를 우선하고 불필요한 서버·스케줄러·DB는 만들지 마.
- 미리보기와 실제 실행을 명확히 나눠줘. 외부 메시지 전송이나 예약 등록은 위에서 지정한 대상과 범위가 있을 때만 수행해줘. 테스트에서는 임시 자료와 시험용 연결을 사용해줘.
- 입력을 검증한 뒤 실행 계획과 안정적인 작업 식별자를 만들어줘. 재시도마다 난수·현재 시간으로 새 작업을 만들지 마. 완료 표시만 믿지 말고 실제 결과가 이번 입력과 일치하는지 확인해줘.
- 결과를 모두 준비한 뒤 완료 상태로 노출하고 실패한 부분 결과는 완료로 처리하지 마. 개인용 순차 실행과 분산 동시 실행 보장을 구분해줘.
- 개인 원본은 data/private/, 로컬 작업 상태와 결과는 앱의 work/·output/에 두고 이 경로의 Git 제외 규칙을 추가·확인해줘. 공개 가능한 samples/만 커밋하고 이미 추적된 개인 파일이 있는지도 확인해줘.
- 직접 의존성과 전이 의존성의 런타임 조건을 확인해줘. 표준 Python만 쓴다면 불필요한 패키지 설치를 추가하지 마. 패키지가 필요하면 앱 전용 가상환경과 잠금 파일을 준비해줘.
- .vibe/project.json에 목표·완료 조건·실제 자동화 검사를 등록해줘. Python은 {python}을 쓰고 가상환경을 쓴다면 cwd 기준 venv를 지정해줘. CI도 현재 프로필 check 후 실제 앱 검사를 실행하게 해줘.
- 미리보기의 무변경, 정상 실행, 같은 요청 두 번, 변경된 입력, 기간 경계·빈 결과, 잘못된 값, 출력 실패, 중간 실패 후 재시도, 불완전·변조된 완료 결과를 실제로 확인해줘. 원본 해시와 결과 내용·필요시 수정 시간을 비교해줘.
- 실제 명령과 python scripts/vibe.py verify를 실행하고, 결과를 여는 명령은 성공한 경우에만 이어가게 해줘. 브라우저 작업이 있는 경우에는 격리된 브라우저에서 실제 흐름을 확인해줘.
- README에 OS별 명령, 반복 실행 기준, 실패 복구, 결과 위치, 실제 예약 여부를 명시해줘. 마지막에는 실제 확인한 결과와 남은 제한을 알려줘. 게시가 범위에 있으면 비공개 자료 제외와 원격 결과까지 확인해줘.
```
