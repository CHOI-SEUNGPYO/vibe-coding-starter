# 병렬 작업 분담

오케스트레이터는 사용자 요청의 전체 완료 조건과 최종 통합을 책임진다. 역할 파일이 있다는 이유만으로 에이전트가 자동 실행된다고 가정하지 않는다. 현재 세션에서 제공되는 다중 에이전트 도구를 확인하고, 없으면 같은 순서를 한 에이전트가 수행한다.

## 나누기 전에 결정할 것

각 작업에 입력, 기대 결과, 수정할 수 있는 파일, 수정하면 안 되는 파일, 완료 조건을 전달한다. 공유 인터페이스가 필요하면 먼저 이름·스키마·에러 처리 계약을 정한다. 분담할 때는 실제 파일 경로나 읽기 전용 범위를 명시한다.

유용한 예:

- 탐색 담당: 관련 구현과 호출 지점, 재현 방법을 읽고 근거를 전달한다. 파일을 바꾸지 않는다.
- 구현 담당: 합의한 파일에서 기능을 연결하고 해당 영역의 검사를 실행한다.
- 검토 담당: 완료 조건과 변경 내용을 독립적으로 살펴 누락·회귀를 찾는다. 구현자의 결론을 정답으로 주지 않는다.

하나의 버그를 고치는 데 담당자를 모두 만들 필요는 없다. 의존 관계가 강한 작업은 순서대로 처리하고, 독립적인 작업만 병렬로 실행한다. 같은 파일의 병렬 편집이 불가피하면 분리된 브랜치나 작업 디렉터리를 먼저 마련한다.

## 진행 중

계약이나 범위를 바꾸면 영향을 받는 담당자에게 즉시 알린다. 이미 실행 중인 작업을 다른 담당자에게 중복 배정하지 않는다. 공유 작업 트리에서는 다른 담당자의 변경을 덮어쓰거나 되돌리지 않는다. 외부 변경 권한은 하위 에이전트에게 맡겼다고 넓어지지 않는다.

## 통합

각 결과에서 바뀐 파일, 확인한 사실, 실행한 검사와 결과, 미해결 항목을 받는다. 최종 담당자가 실제 변경과 검증 결과를 확인하고 통합 검사를 수행한다. 하위 에이전트의 “완료” 메시지만으로 전체 성공을 선언하지 않는다.
